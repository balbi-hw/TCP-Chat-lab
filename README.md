# 실시간 멀티스레드 채팅 서버 / 클라이언트 구현

> [261029 ~ 261031] 학습용 실시간 멀티스레드 채팅 서버 / 클라이언트 구현 프로젝트 입니다.

## 개요

개발자로서 성장해 나가는 데에 도움이 될 기초 지식들을 배우기에 적합한 프로젝트가 될 것이라는 추천 및 조언을 받아 직접 한 번 진행해보았습니다.  
  
조언 대로 정말 많은 내용을 배울 수 있었고 학습 키워드도 많이 얻을 수 있었습니다. 실시간 채팅 구현 자체가 꽤나 큰 작업이었다는 점을 깨달았고 동시에 제가 얼마나 부족한지 또한 같이 깨달았습니다.  
  
OS, 프로세스, 스레드가 어떻게 동작하는지 그 구조를 조금이나마 엿볼 수 있었고 실시간 통신의 전체적인 구조를 파악할 수 있었습니다. 진행하며 보고 사용한 지식들이 모두 다 이해가 되지는 않았지만 앞으로 조금씩 채워나가려합니다.
  
처음부터 다시 훑어보며 개념을 탄탄히 잡고 응용할 수 있도록 하고 싶습니다. 마침 바이브 코딩으로 진행하던 프로젝트 기능 중 메신저 기능이 있었는데 그 기능 개발에도 큰 도움이 될 것 같습니다.


## 실행 방법

세 파일을 컴파일 한 뒤 콘솔에서 서버를 띄우고 클라이언트를 여럿 띄운 뒤 채팅을 진행하면 작동하는 것을 확인하실 수 있습니다.

```
# 컴파일
javac -encoding UTF-8 -d out \
  src/ChatServer.java \
  src/ClientSession.java \
  src/ChatConsoleClient.java

# 서버 실행
java -cp out ChatServer

# 다른 터미널에서 클라이언트 실행
java -cp out ChatConsoleClient
```

## 데이터 흐름

Reader Worker -> Broadcast -> Queue -> Writer

Reader 가 메시지를 수신하여 읽고 소켓이 연결되어 있는 각 세션별 Queue 에 메시지를 추가합니다.  
이후 추가된 메시지는 각 세션 내의 Writer 가 수신하여 콘솔에 출력합니다.

## 통신 프로토콜

통신 프로토콜은 우선 개념을 확인하는 정도로 간단히 구현해두었습니다.

본문 : `MSG <본문>\n`  
종료 : `QUIT\n`

## 동시성 처리

`synchronized` 를 활용해 세 가지 Lock 을 만들어 원자성 처리를 했습니다.

`registryLock`, `broadcastLock`, `stateLock`
  
세 가지 Lock 을 활용하였으나 각 Lock 이 담당하는 부분에 대해서는 아직 추상적인 이해밖에 하지 못해 추후 살펴보며 왜 세 가지 종류가 필요한지 각각의 역할이 무엇인지 이해하려 합니다.

## 장애 처리

각 세션 별 `Queue` 의 최대 크기를 10으로 잡아 이 이상 메시지가 들어오게 되면 연결을 종료하도록 설계하였습니다. 또한 의도적인 종료와 장애로 인한 종료가 두 번 처리되지 않도록 멱등성을 고려하였습니다.
